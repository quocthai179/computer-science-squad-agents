# /lab:analyze

You are the Lead. `analyst` analyses; `skeptic` critiques; the user decides.

Language: the project language is `language:` in `research/PROJECT.md`; if it is blank, the plugin default `${user_config.language}` (if that still shows as the literal text `${user_config.language}`, the option is unset: use English) (rules in ${CLAUDE_PLUGIN_ROOT}/playbooks/language.md). Reply to the user in the language they write in. Put `language: <code>` in every TASK BRIEF.

Rules that always hold:
- Every number in FINDINGS.md is in `tables/` generated by `ledger.py`/`stats.py`, with `[run:...]`.
- The person who ran the experiment does not grade it: do not call `experimenter` here.

Input: $ARGUMENTS

## Steps

1. Read `research/experiments/<exp_id>/PLAN.md` and `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/ledger.py list --exp <exp_id>`. No `ok` run besides smoke: stop and suggest `/lab:run-exp`.
2. Identify the main comparisons from PLAN.md (baseline vs method, ceiling, ablations).
3. Call `lab:analyst` with a TASK BRIEF:
   - `inputs: PLAN.md, runs.jsonl` of <exp_id>; the list of comparison pairs; `primary_metric`
   - `output: research/experiments/<exp_id>/FINDINGS.md`, template `${CLAUDE_PLUGIN_ROOT}/templates/<language>/findings.md`; `tables/` and `figures/` come from scripts
   - `playbook: ${CLAUDE_PLUGIN_ROOT}/playbooks/experiment.md`
   - absolute paths `${CLAUDE_PLUGIN_ROOT}/scripts/ledger.py`, `stats.py`, `lint_report.py`
4. Call `lab:skeptic` with type `findings`, giving the paths of FINDINGS.md, PLAN.md and runs.jsonl only. Review at `research/reviews/<exp_id>-findings-<YYYY-MM-DD>.md`.
5. Present to the user: a 5-line summary of FINDINGS, the main table (copied from `tables/`), the skeptic's verdict and blocking issues, and the comparison with the prediction.
6. **The user decides** one of three:
   - more evidence needed → suggest specific runs, back to `/lab:run-exp`;
   - change the hypothesis → `/lab:design-exp` with a new PLAN (the old PLAN stays as it is);
   - enough, or a kill criterion was hit → close: `status: closed` in PLAN.md, the conclusion and the "why" in FINDINGS.md.
7. Resolve calibration using the id at the end of PLAN.md: `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/calibration.py resolve <id> --outcome <true|false|partial>`; for the estimate, ask the user for the actual hours and use `--actual-hours`.
8. Record in `research/decisions.md` and `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/notebook.py add --source analyze "<exp_id>: <one-sentence conclusion>; decision: <...>"`.
